# 施工指南 · 嵌入式引擎集成

> 把 yoma/engines 的能力引擎(Rust + Python)接进 my-pi 内核的方式与理由。
> 日期:2026-07-29。参考实现:yoma `packages/opencode/src/tool/embedded.ts` 与 `engines/build.ts`。

---

## 1. 一句话

**语言不进内核,进程边界进内核**:每个引擎都是黑盒 CLI(argv 进、JSON 出),
TS 侧只有三件事 —— 路径解析、spawn、把 stdout 整形给模型。
Rust(stm32kernel / probe-rs)编译成静态二进制,Python(controller_map)经 uv venv
的 console-script 入口点,本质上也是可执行文件;运行时没有一行代码知道对面是什么语言。

```
packages/coding-agent/src/core/tools/
  engines.ts          # 共享辅助(同 path-utils.ts 一类):engineBin/engineDataDir 路径解析
                      # + runEngine argv spawn(超时/中断 SIGTERM→3s→SIGKILL,settle 有界)
  netlist.ts          # 原理图 → 引脚图 / board IR(controller_map、board_ir)
  stm32config.ts      # 配置文档 → 校验/生成驱动工程(stm32kernel)
  flash.ts            # 烧录与目标控制(probe-rs;非零退出=正常结果+指引)
  datasheet.ts        # 数据手册三动作合一(search/read_section/view_figure),全在线,见 §5
engines/              # 三个 git submodule + build.ts(构建 + 安装 + doctor)
```

## 2. 单一布局:engines/bin + engines/data

运行时只认一种形状,没有第二种:

```
engines/bin/    stm32kernel  probe-rs  controller_map  board_ir  connections
engines/data/   stm32/(irpacks + fw)
```

`bun engines/build.ts` 构建完把产物**符号链接**进来(重新 cargo build 立即生效,
不占双份磁盘;两个目录在 .gitignore 里)。解析代码因此只有一个 `engineBin(name)`:
默认从模块位置向上找仓库的 `engines/`,测试/特殊场景用 options 显式传 `enginesDir`。
将来打包分发时,CI 往同样的 `bin/`、`data/` 里放真文件(Rust 直接 cargo 产物,
controller_map 用 PyInstaller 冻结,零依赖零风险),运行时代码一行不改。

## 3. 换一台电脑

```sh
# 一次性:装 rustup + uv + bun
git clone --recurse-submodules <my-pi>
bun engines/build.ts          # submodule 自动 init + cargo×2 + uv sync + 安装 + doctor
```

版本一致性是自动的:`rust-toolchain.toml` 钉 Rust,uv 自动下载 Python 3.13,
`packageManager` 钉 bun。构建产物(target/、.venv/、bin/、data/)不进 git,每台机器各自重建。

## 4. 工具移植清单(yoma → my-pi)

| yoma 工具 | 引擎 | 状态 |
|---|---|---|
| stm32config | stm32kernel(Rust) | ✅ 已移植,含 buildArgs 纯函数 + 假内核测试 |
| netlist | controller_map/board_ir(Python) | ✅ 已移植;map/board_ir 双模式,ODrive fixture 真机验证 |
| flash | probe-rs(Rust) | ✅ 已移植;非零退出按正常结果返回(接探针指引) |
| datasheet(单工具) | 同事的文件服务器(全在线,零本地) | ✅ read_section/view_figure 已可用;search 等服务器 /api/search 上线(契约见 §5) |

移植要点(以 stm32config 为样板):描述文本从 yoma 原样搬(是调过的,别重写);
exit 1 + stdout 有 JSON = 正常结果附修复指引,exit 2 或 stdout 空 = 抛错;
路径参数一律 `resolveToCwd` 到会话 cwd;引擎缺席时报"跑 `bun engines/build.ts`"。

## 5. datasheet 工具:完全在线,零本地状态

【有意决策 2026-07-30】数据手册工具**不落任何本地状态**:不装索引、不缓存产物、
不需要 SiliconFlow key。三个动作合在一个 `datasheet` 工具里(action 模式,同 flash),
一切按需从同事的文件服务器读取,本机唯一的配置是环境变量 `YOMA_DATASHEET_SERVER`。

- `read_section`:GET `{server}/artifacts/<parsed_path>` → 本地纯逻辑抽章节 ✅ 已可用
- `view_figure`:GET `{server}/artifacts/<image_path>` → ImageContent,模型直接读图,
  Zed 工具卡片同步显示(toolContentOf 实时+重放两条路径都透传 image 块)✅ 已可用
- `search`:POST `{server}/api/search` —— **服务器端点尚未实现**,需要同事在
  数据手册服务器上加(embedding 的 SiliconFlow key 也随之收进服务器,客户端零凭据):

```
POST /api/search        Content-Type: application/json
请求  { "query": "...", "chip": "STM32F1", "rev": "RM0008"?, "top_k": 6 }
响应  { "hits": [ { "text", "manual_name", "chip", "rev", "page", "headings",
                    "score", "kind", "source_pdf", "parsed_path", "image_path" } ] }
语义  服务器端 bge-m3 query embedding(与摄入端同编码器)+ Lance vectorSearch
      (cosine,score = 1 - distance)+ chip 过滤(rev 省略时并入 GENERAL 桶,
      给了 rev 则只查该手册)+ 去重排序。字段与 rag_yoma 11 列 chunks 表一致,
      rag_yoma/query.py 已有同逻辑的 Python 实现可直接搬。
```

端点上线前,search 动作会返回引导信息(指向本节);read_section/view_figure 不受影响。
RAG_yoma(建索引管线)只属于建索引的人,永远不进 my-pi。
