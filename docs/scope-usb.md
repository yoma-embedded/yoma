# SDS824X HD USB 接入与验收

2026-09-16。当前目标是让 agent 设置示波器、采集并读取证据，让工程师在前端查看同一份波形。接线、探头档位、焊接和更换元件由人完成。例程库及其他功能不在这次范围内。

## 已实现的链路

`scope` 工具 → `host/domain/scope` 的 USBTMC / SCPI 驱动 → 仪器。执行与设备占用由宿主负责；前端只通过菜单的三个只读接口读取磁盘。上游发动机保持原样。

- `devices / connect / status`：发现仪器、按序列号选择、读取型号与设置。首期只接受 SDS824X HD USB。
- `setup / measure`：设置通道、时基、触发、存储深度，读回实际设置与仪器量测结果。
- `capture`：冻结当前记录，或等待新的单次触发。默认保存每一个样本，每通道最多 200 万点；记录超出预算会报错，先减小存储深度。
- `arm / collect`：先布置触发，再进行复位、烧录或人工动作，最后收取。等待超时保持武装状态，可以继续 collect；stop 结束本次等待。
- `list / samples`：离线读取历史采集及有界采样窗口，不需要连接示波器。
- `screenshot / stop / disconnect`：读取屏幕、结束武装、释放设备。

前端调试面板中的示波器视图支持通道开关、缩放、平移、A/B 游标和仪器截图。缩小时每列保留最小值与最大值，避免简单跳点漏掉窄脉冲；放大后显示实际保存的样本。概览采集明确标注抽样，不能用来排除毛刺。电流 A 与电压 V 按单位分组切换，当前没有同时双纵轴显示。

波形图是已保存记录，不是持续刷新的实时仪器屏幕。历史视图的缩放和游标不会向 USB 发命令。

## Agent 操作顺序

1. 说明测点、通道、地线和物理探头档位，等待人确认。USB 无法知道探头真正接在哪。
2. devices → connect → status；多台仪器时按序列号选择。
3. setup 并核对读回。示例：C1、10× 探头、1 V/div、500 μs/div、1M 存储深度、C1 上升沿 1 V。
4. 周期信号可用单次 capture；复位/上电等瞬态用 arm → 动作 → collect。
5. 引用采集编号、通道、时窗、采样间隔和测量结果，给出观察与下一步；需要移动探头时再次等人确认。

例如已确认接线后，agent 可以调用：

```json
{"action":"setup","channels":[{"ch":1,"on":true,"probe":10,"vdiv":1,"coupling":"DC"}],"timebase":{"scale":0.0005},"trigger":{"mode":"auto","source":"C1","slope":"rising","level":1},"mdepth":"1M"}
```

```json
{"action":"capture","mode":"single","channels":[{"ch":1}],"quality":"exact"}
```

物理探头不是 10× 时，示例中的 probe 必须按实际修改。

电流探头须先确认转换比例、归零和夹持方向。本次 Little Bee H1 由用户确认是 **1 V/A**、已经归零，CH1 因此设 `unit: "A", probe: 1`；只把显示单位改成 A 并不能校准未知探头。探头带宽与转换比例是两个参数，不能相互推算。

## 证据与恢复

每次采集独立保存在 `<工程>/.yoma/scope/<id>/`：`capture.json`、各通道 `cN.i16`，以及可选 `screen.png`。元数据最后写入，半成品不会列为成功采集；旧编号不能覆盖。元数据保存实际比例、探头系数、每通道时间轴、记录点数与抽样率。截图单独带时间戳；截图失败会明确报告，波形仍可保留。

默认采集截图同时返回给 agent；大截图留在磁盘。原始大数组不放进聊天历史。独立截图在 `.yoma/scope/screens/`，本机 USB 地址在 `.yoma/scope/config.json`；整个目录自带 Git 忽略规则。

同一仪器同时只给一个工具会话使用，arm 期间保留占用。USB 出错或取消后关闭连接，等待原生传输结束再释放资源；截图期间取消可能等待当前传输超时，约 15 秒。重试前重新连接。外部控制程序及仪器前面板不受此进程内占用控制，采集时应保持设置不变；读波形前、各通道后和截图后会检查停止状态。

## 继承的真机协议事实

以下来自停车目录的 2026-09-04 记录，设备固件为 `4.8.12.1.1.6.5`；它们指导当前驱动，不能替代本次验收。

- WORD 波形按小端读。WAVEDESC 的增益与偏置不含探头倍数；BYTE 的比例和字节序描述有固件怪癖，因此工具固定使用 WORD。
- 时间轴按 `delay − 5 × timebase + index × interval × stride` 计算；每通道保存自己的比例与时间轴。
- 实际记录长度取描述块的 WAVE_ARRAY_COUNT；采集配置点数可能还对应另一个时基，不能据此越界请求。
- MAXPoint 限制源点窗口，分段起点按已交付点数乘 stride 推进；块尾可能有两个换行。
- 截图返回裸 PNG；走到 IEND 判断完整性。
- 超时残留可跨客户端存在，USB CLEAR 未必清空响应；连接时清理残留，查询超时后重新连接。
- 通道、触发、存储深度必须读回；仪器可能静默忽略设置或改写触发源。量测通过 ADVanced 槽位读取，`****` 表示无有效量测值。

## 2026-09-16 真机结果

Mac USB 连接 SDS824X HD，序列号 `SDS08A0D910802`，固件 `4.8.12.1.1.6.5`。CH1 是用户已归零的 Little Bee H1，1 V/A，夹在地线；CH2 是 1× 探头接仪器校准输出。

首次联调能识别仪器并截图，但设置后的读回反复超时；停车目录旧驱动与新驱动均复现，拔插 USB 也未恢复。用户给示波器断电重启后，设置、波形读取和量测恢复正常。**这是恢复事实，不是根因结论；不能声称重启已经修复软件，或把故障归因于 FFT。** 尚未找到稳定的软件恢复方式。

实测还发现旧统计会把 CH1 不规则穿越的中位间隔报成约 2.4 MHz。现已增加保守筛选：至少 3 个完整上升间隔，90% 以上在中位数 ±20% 内，才给频率、周期和占空比估计。两份真实记录中 CH1 的误报已消失，CH2 的约 999.92 Hz 保留；均值、RMS 和原始数据不变。这个筛选不是周期性证明，缺少估计也不表示频率为零。

## 真实 Yoma agent 自主验收

2026-09-16 追加：在构建后的独立 Yoma 桌面窗口，用真实聊天输入框提交测量任务。模型为已配置的 **DeepSeek V4 Flash / max**，通过正常 renderer → preload → kernel → agent → scope → USB 路径执行。隔离的是桌面会话与工程目录，没有注入假模型，也没有预先复制旧波形；验收未重启用户已有应用。

这一轮用时约 237 秒，32 次工具调用，其中 12 次为 scope。agent 自行发现仪器、读取配置、STOP、保存当前双通道记录、做仪器量测及离线核对、恢复 RUN、确认 Trig'd 并 disconnect。12 次 scope 调用均成功。临时离线分析脚本曾越界报错，模型自行修正后继续；这不是驱动或 provider 失败。

- 新采集：`scope-524929e1-355a-41c1-b813-592211b72119`，每通道 50 万连续点、100 MSa/s、5 ms；前端自动选择的编号与工具结果一致。
- CH1 保存数据独立复算均值 73.620186 mA，仪器 MEAN 73.62018 mA；该窗口最小/最大约 50.729/97.708 mA。
- CH2 仪器 FREQ 999.91758 Hz，AMPL 2.96667 V，PKPK 3.000 V；AMPL 与 PKPK 含义不同。模型离线过沿复算约 999.91667 Hz。
- STOP → 保存 → measure 之间未恢复运行或改采集设置，操作记录支持同冻结帧比较。**数字吻合本身不能证明同帧，更不意味着探头或仪器有七位测量准确度。**
- 前端聊天、工具结果和新波形已人工检查，窗口没有运行时异常或 console 错误。

证据在本机 `.yoma/scope/acceptance-20260916/agent-e2e-1789548827940/`：原始 `messages.json`、`final-answer.md`、`agent-result.png`、`agent-waveform.png`、会话 JSONL、采集副本及 `audit.json`。原始 runner 有一条“编辑框文本完全相等”的失败：富文本增加了空行；核对实际提交的用户消息后，忽略空白的内容一致。保留了原始失败记录，未把它改成全绿。

结论：**真实 agent 自主使用示波器的主链路通过，报告质量与效率仍需打磨**。本轮暴露的后续项：

1. 基本均值/频率/幅度测量优先使用工具汇总与仪器量测，避免为了简单任务反复写脚本和做未要求的 FFT。
2. 明确区分保存样本推算与仪器量测。模型曾把 samples 的磁盘过沿叫作“仪器端时间戳”，最终又用“不同帧不可能如此吻合”作过强论断。
3. 模型以 `~` 书写多组数值区间时，聊天 Markdown 把其中一段显示成删除线；应修正区间书写或渲染规则。

这些是实测发现的待改进项，尚未通过更改提示词或产品代码进行第二轮验证。截图供人查看；本轮数值分析不能证明非视觉模型理解了 PNG。
