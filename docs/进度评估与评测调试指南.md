## 二、与参考实现的实质差距

1. **`prepareNextTurn` / `shouldStopAfterTurn` 声明了但从不调用**（types.ts:220/213 有声明，loop 里没有对应参考 agent-loop.ts:232-263 的代码）。调用方传入会被静默忽略。M7 的 save-point 机制依赖 `prepareNextTurn`，必须补。
2. **abort 语义分叉**：my-pi 在 `turn_end` 后提前 `return`（agent-loop.ts:213-216）；参考做法是下一轮 stream 返回 `stopReason: "aborted"` 的助手消息收尾。中途 abort 时 transcript 可能留下未应答的 toolCall。
3. agent.ts 少 8 个配置项：sessionId、onPayload、onResponse、transport、thinkingBudgets、maxRetryDelayMs、prepareNextTurn、prepareNextTurnWithContext。
4. 配置腐化：tsconfig 写 `examples/**` 但目录叫 `example/`（example 不参与 typecheck）；package.json 的 `"./node"` export 指向 0 字节文件。

## 三、调试方法：先用仓库自带的（全离线、零 API 费）

pi-minimal 的测试体系分三层，**你的 agent-loop.ts 保留了 `streamFn` 注入缝，参考测试可几乎原样移植**：

1. **Mock streamFn（测 loop）**：测试里造 `MockAssistantStream extends EventStream`，用 `queueMicrotask` 推手写的助手消息（第 1 次返回 toolCall，第 2 次返回文本），收集全部 AgentEvent，**断言有序事件类型序列** + 工具真实执行的副作用。参考：`test/agent-loop.test.ts`（1424 行）。
2. **Faux provider（测完整 Agent 链路）**：`fauxProvider()` 注册进真实 `createModels()`，`setResponses([...])` 编排剧本（支持检查请求内容的工厂函数），真实 streamSimple 管线切成 delta 流。本地已有：`packages/ai/src/providers/faux.ts`。参考：e2e.test.ts 和全部 harness 测试。
3. **纯 fixture（测 compaction/session）**：手工构造 `SessionTreeEntry[]`，不碰 LLM。

## 四、业界怎么做（Anthropic / OpenAI）

### Anthropic

- 方法论核心：[Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)
  - **Grader 三级阶梯**：代码判定（精确匹配/测试通过/结果校验）→ LLM-as-judge（须人工校准）→ 人工评审。
  - **区分轨迹与结果**："给 agent 产出打分，不给路径打分"；但**读 transcript 是核心调试实践**。
  - **pass@k vs pass^k**：k 次过 1 次 vs k 次全过；一致性要求高看 pass^k。
  - 起步：从 20–50 个真实失败造任务，隔离环境跑。
- Claude Code 本身：极端 dogfooding（80%+ 内部工程师日用）+ feature-flag A/B；[质量事故复盘](https://www.anthropic.com/engineering/a-postmortem-of-three-recent-issues)承认 evals 太噪，补救是"在真实生产系统上持续跑 eval"。
- 发布基准：SWE-bench Verified、Terminal-Bench、τ2-bench、OSWorld、Aider Polyglot，每项平均 5 次独立试验。

### OpenAI

- Agents SDK **默认全量 tracing**（生成/工具调用/handoff 皆为 span）+ Traces dashboard；调试入口是 "trace grading"。
- SWE-bench Verified 由 OpenAI 制作；Codex 用 SWE-bench Verified、SWE-Lancer、Terminal-Bench 2.0 评。
- ⚠️ OpenAI Evals 平台退役中（2026-10-31 只读，11-30 关闭），别在上面建东西。

### 共同模式

确定性 grader 优先 → 校准过的 LLM 判官 → 人工；从生产失败挖 eval 用例；docker 沙盒任务环境做底座；每题重复多次报 pass@k；**读 transcript 是共同的核心调试手段**。

## 五、落地方案（solo TS 开发者三件套）

1. **可 mock 的模型边界 + 录制/回放**：先移植参考测试；再给 agent 加 `--record`/`--replay`，把 stream 事件按 JSONL 落盘，失败现场即 fixture。⚠️ Anthropic API 无 seed 参数、最新模型已移除 temperature——**录制/回放是复现非确定性失败的唯一可靠手段**。
2. **Tracing + transcript 查看器**：[Langfuse](https://langfuse.com/self-hosting)（MIT 可自托管，TS SDK v4 基于 OTel）或 [Phoenix](https://github.com/arize-ai/phoenix)（单容器本地）；JSONL 日志配 [claude-code-trace](https://github.com/delexw/claude-code-trace) / [AgentPrism](https://evilmartians.com/chronicles/debug-ai-fast-agent-prism-open-source-library-visualize-agent-traces)。配合 [Hamel 式错误分析](https://hamel.dev/blog/posts/evals-faq/)：读失败轨迹→打标签→修最大类→重跑（全流程 ROI 最高的一环）。
3. **15–30 题小评测套件，nightly 跑 pass@3**：每题 = 隔离环境 + 指令 + 确定性验证器。用 Terminal-Bench 任务格式写，日后可 `harbor run` 跑真 [Terminal-Bench 2.0](https://www.tbench.ai/)（本地 Docker，约 $5–50）做外部校准；第二基准用 SWE-bench Lite 子集 + [sb-cli](https://github.com/SWE-bench/sb-cli) 免费云端判分。

框架选型：in-repo 评测用 [evalite](https://github.com/mattpocock/evalite)（Vitest 基座）或纯 Vitest；要 CLI 矩阵和 llm-rubric 断言加 [promptfoo](https://www.promptfoo.dev/)。
