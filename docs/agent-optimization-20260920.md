# 2026-09-20 Agent 优化与首轮评测

已落地两项产品改动和一套小型行为回归评测。当前结果支持继续沿这个方向验证，但不能证明对所有嵌入式任务都有效。

## 产品改动

1. **grep 合并重叠上下文。** 每个文件行只返回一次，真正命中仍用 `:` 标记。同一文件按最高所需行号做一次有界读取。密集命中的测试原先返回 1838 行重复内容后被 50KB 上限截断；修复后完整保留两个文件的全部 200 行证据。
2. **全局提示词使用通用规则。** 区分配置/指令、软件报告、推导量、直接观测；证据对应当前版本与测试区间；观察冲突时修正结论；认可已有充分测试记录；重试前先判断哪个条件发生了变化。电机与 RPM 不写入全局规则，具体场景放在评测里。

没有改上游四个锁定包，没有改变生产调试台的预算或停止策略。桌面构建已更新，未重启正在运行的 app 或内核；现有进程不会自动加载新内核。

## 最终对照

模型 `deepseek/deepseek-v4-flash`，实际思考档位 `high`。旧版提示词取自本轮修改前的 Git HEAD，最终版与旧版使用相同的 13 个合成用例、工具契约和限制。每题一次，模型输出上限 2048 token、最多 8 次生成、90 秒，传输最多重试两次。没有挑选每题最好的一次。

| 指标 | 原提示词 | 最终通用提示词 |
|---|---:|---:|
| 严格通过（包含 JSON 格式要求） | 10/13 | 11/13 |
| 模型生成次数 | 45 | 36 |
| 工具调用 | 45 | 35 |
| 输入 token（含缓存） | 131,800 | 108,199 |
| 输出 token（已包含 reasoning） | 16,958 | 10,914 |
| reasoning token（输出的子集） | 13,196 | 7,947 |
| 已记录用量的估算费用 | $0.006886 | $0.006596 |

新增的 ADC 实际速率、GPIO 锁存器与物理电压、发送队列与远端收包三题，两版都是 3/3；这三题的模型请求合计 9 → 6。它表明此次改动并非只能套用电机场景，仍不足以证明广泛泛化。

**最终版的两处失败是输出格式。** `empty-log` 给出正确字段但添加了 JSON 外的解释；`verified-communication` 正确认可了合格的通信记录，但 JSON 字符串漏了结束引号。严格判分均不通过，未人工改成通过。原版还出现了拒绝采纳用户现场观察、将“未验证”写成 false，以及通信阳性题两次耗尽输出额度仍没有最终答案。

只有一次完整的最终对照，没有独立盲测集，不作统计显著性或真实硬件任务成功率声明。缓存状态没有控制；最终版非缓存输入实际上更多（23,591 对 12,888），所以不能将模型请求减少 20% 说成 API 费用也减少 20%。这些是简化的工具结果环境，尚未证明完整工程探索、编译、烧录、长期上下文或真机闭环的改善。

## 实验过程与费用

共保存 97 次试验结果、317 次模型生成请求，包含连接失败、早期 fixture 校准、被替换的电机特例提示词，以及最终对照。已记录 usage 加首次连通探针的总估算费用约 **$0.0481**；价格来自本地模型目录，未返回 usage 的连接错误/中断不代表账单必然为零。原始结果保存在本机 `.yoma/evals/2026-09-20/`，不会提交用户历史对话或凭据。

早期模拟 log 对所有动作返回同一段文本，模型合理地质疑了它；另一个早期判据混淆了“未验证”和“验证失败”。两者已修正，旧分数保留用于审计，**不纳入最终对照**。中间两组因保守费用预留触限而不完整，也不合并到最终分数。最终对照目录是 `final-baseline-13` 与 `final-generic-13`。

## 工程验证

- 强制类型检查：11/11 包，加根目录，通过。
- bench + kernel 回归：37 个文件、374 个测试通过；随后最终评测/grep/prompt 定向复核 40 个测试通过、2 个平台条件跳过。
- Windows 子进程测试：41 通过、1 条仅 Electron 运行时适用的用例跳过。初次沙箱/默认时间限制下失败，使用正常子进程权限与仓库 CI 的宽限时间复核通过；未为测试修改产品超时。
- 上游源码与生成快照哈希检查、改动文件 lint、桌面生产构建通过。
- 构建产物 smoke 的内核加载（17 工具）与 USB 模块加载通过；完整 smoke 被本机缺少 `engines/bin/stm32ck-import.exe` 阻断。没有宣称整个 smoke 通过。

## 后续优先级

先把更多真实失败归为通用故障类型，为每类建立可信 fixture 与独立判据，再扩充按项目分开的留出集。完整任务继续复用已有 Harbor / `eval/entry.ts`，真机测试独立串行运行。后续模型、思考档位、工具描述或上下文裁剪的选择，应比较同一套任务的成功率与每个成功任务的摊销成本。

用法见 [行为评测说明](agent-behavior-eval.md)。目前已经具备可复跑基线、费用限制、工具轨迹与失败分类的起点；不需要先建设复杂的评测平台。
