# 桌面版发布流程

Windows 桌面版由 `.github/workflows/desktop-win.yml` 发布。正式发布不需要手动进入 Actions 点按钮：
推送与应用版本一致的 `v*` tag 后，GitHub 会自动构建、验收并创建 Release。

## 发布一个版本

1. 修改 `packages/desktop/package.json` 的 `version`，例如 `0.1.1`。
2. 合并并确认 `ci` 通过。
3. 在准备发布的提交上创建并推送同版本 tag：

   ```bash
   git tag v0.1.1
   git push origin v0.1.1
   ```

tag 与包版本不一致时，发布会直接失败，避免生成版本号错误、无法自动更新的安装包。

## 自动验收与产物

每次 tag 发布都会在全新的 Windows runner 上完成：

1. 构建 prod 渠道的 Windows x64 NSIS 安装包。
2. 检查随包引擎都是 Windows PE 文件。
3. 静默安装到干净临时目录。
4. 从安装后的 `app.asar` 启动真 preload 与真 kernel，并创建首个会话。
5. 生成 SHA-256 校验和与 GitHub 自动 release notes。
6. 发布以下文件：

   - `yoma-win-x64.exe`：安装包
   - `yoma-win-x64.exe.blockmap`：增量更新数据
   - `latest.yml`：`electron-updater` 使用的版本与下载元数据
   - `SHA256SUMS.txt`：下载校验和

仍建议每个重要版本在一台真实、未安装过 Yoma 的 Windows 电脑上手动走一次：下载、SmartScreen
提示、安装、配置 API key、创建会话。这一步用于发现虚拟 runner 覆盖不到的驱动、杀毒软件和显示环境问题。

## 手动构建

Actions 里的 `desktop-win` 仍支持手动触发，可选择 `prod`、`beta` 或 `dev`，产物只作为临时
artifact，不会创建正式 Release。正式 Release 只接受 `v*` tag，并固定使用 `prod` 渠道。

目前 Windows 安装包未签名。配置代码签名证书之前，README 必须保留 SmartScreen 说明。
