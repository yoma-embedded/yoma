# 桌面版发布流程

Windows 桌面版由 `.github/workflows/desktop-win.yml` 发布。正式发布不需要手动进入 Actions 点按钮：
推送与应用版本一致的 `v*` tag 后，GitHub 会自动构建、验收并创建 Release。

## 发布一个版本

1. 修改 `packages/desktop/package.json` 的 `version`，例如 `0.1.1`。
2. 合并并确认 `ci` 通过。
3. 在准备发布的提交上创建并推送同版本 tag：

   ```bash
   git tag v0.1.1
   git push origin v0.1.1
   ```

tag 与包版本不一致时，发布会直接失败，避免生成版本号错误、无法自动更新的安装包。

## 自动验收与产物

每次 tag 发布都会在全新的 Windows runner 上完成：

1. 构建 prod 渠道的 Windows x64 NSIS 安装包。
2. 检查随包引擎都是 Windows PE 文件。
3. 静默安装到干净临时目录。
4. 从安装后的 `app.asar` 启动真 preload 与真 kernel，并创建首个会话。
   随后从安装目录运行引擎冒烟：启动五个必需引擎、解码 LA 演示波形；有 irpack 时实际加载器件库，缺失则明确记录跳过。
5. 生成 SHA-256 校验和与 GitHub 自动 release notes。
6. 发布以下文件：

   - `yoma-win-x64.exe`：安装包
   - `yoma-win-x64.exe.blockmap`：增量更新数据
   - `latest.yml`：`electron-updater` 使用的版本与下载元数据
   - `SHA256SUMS.txt`：下载校验和

仍建议每个重要版本在一台真实、未安装过 Yoma 的 Windows 电脑上手动走一次：下载、SmartScreen
提示、安装、配置 API key、创建会话。这一步用于发现虚拟 runner 覆盖不到的驱动、杀毒软件和显示环境问题。

## 手动构建

Actions 里的 `desktop-win` 仍支持手动触发，可选择 `prod`、`beta` 或 `dev`，产物只作为临时
artifact，不会创建正式 Release。正式 Release 只接受 `v*` tag，并固定使用 `prod` 渠道。

目前 Windows 安装包未签名。配置代码签名证书之前，README 必须保留 SmartScreen 说明。

## 引擎和数据的交付边界

- `engines/build.ts --dist` 产出 `bin/`、`data/` 和 `manifest.json`。普通分发要求至少 20 个 irpack；
  它们不进 Git，但会复制到 `data/stm32/`。Windows CI 显式传 `--allow-missing-irpacks`，所以构建成功不代表器件数据齐全。
- `stage-engines.ts` 校验 manifest 中的二进制 SHA-256 与 irpack 数量，再将文件实体化到 `.engines-stage/`。
  安装后位于 `resources/engines/`，main 将这个目录传给内核；`YOMA_ENGINES_DIR` 可显式替换整个引擎根目录。
- 缺 irpack 时，`stm32config schema` 和不带 `part` 的原始网表解析仍可用；其余 STM32 配置命令和 `board_ir` 不可用。
  用户需要包含器件数据的引擎分发包。源码构建者安装 CubeMX 或设置 `STM32CK_CUBEMX_DB` 指向含 `mcu/` 的数据库目录，
  再运行 `npm run engines:build -- --dist`。当前没有安装器内的器件数据下载功能。
- HAL/CMSIS 是另一份资源，manifest 中为 `firmware: "not-bundled"`，普通分发不带它。
  源码构建者可在 `engines/stm32-config-kernel` 运行 `tools/fetch-fw.ps1` 按族获取；原生 CLI 可用 `--fw-dir` 指定目录。
  当前 `stm32config` 工具固定使用引擎目录的 `data/stm32/fw`，尚无独立目录参数或自动获取；完整工程生成与编译仍需单独验收。

安装后的验证命令（PowerShell，需本仓的 npm 依赖与 Electron 测试运行时）：

```powershell
$env:YOMA_DESKTOP_DIR = 'C:/path/to/Yoma/resources/app.asar'
$env:YOMA_ENGINES_DIR = 'C:/path/to/Yoma/resources/engines'
npm run smoke -w packages/desktop -- --require-stm32-data
```

`--require-stm32-data` 用于必须支持 STM32 的验收，缺数据时失败。发布 CI 目前允许明确跳过数据；
冒烟不烧录、不连接硬件，也不代替完整工程生成、驱动或真实板子验收。

2026-09-15 核对：`engines.lock.json` 指向的 `engines-v0.2.0` 在仓库 Release 中不存在，手动 `prebuilt` 路径暂不可用。
请使用本机构建的自包含目录（`YOMA_ENGINES_DIR`），或先发布并核实对应平台的引擎资产后再更新钉子。
