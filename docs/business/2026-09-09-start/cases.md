# 已有案例与下一步验证

记录日期：2026-09-09。来源：Ben 在本次对话中的描述，原始材料尚未检查。

## C01：网表与手册辅助排障

Ben 描述：同事发送原理图网表信息，Yoma 迅速根据手册数据库识别硬件设计问题，并用软件规避。

已有信号：存在其他工程师提供的实际材料；输出关联到一个具体工程问题和处理办法。

待核实：芯片/器件、原始现象、实际设计问题、手册引用、软件改动、是否上板验证、适用条件、人工提示与时间、对方原有排查方式及是否愿意再用。

商业假设：软硬件联合排障或连接/配置约束检查能为研发与 FAE 提供价值。尚不能宣称避免改板、节省多少工时或长期可靠修复。

Agent 接到材料后的工作：

1. 还原输入 → 发现 → 手册证据 → 修改 → 验证，明确每步证据和缺口。
2. 整理一页案例，分别写事实、假设与未验证范围。
3. 如需要重跑，使用不含已知答案的新会话；结果仅验证工作链可重复，不作为独立成功案例。
4. 设计与同事现行方法的比较：相同原始资料、任务与可用时间，记录模型、人为提示和取证条件。单例结果不外推普遍提效。
5. 原同事核对后，再争取一个由对方选择的同类真实问题。

## C02：M5Stack 表情动效创作

Ben 描述：在 M5Stack 模块上，以普通玩家式提示词、未在提示中提供嵌入式专业知识，完成动图表情包导入并适配 MPU6050 实现动效。

已有信号：自然语言意图可以转化为可见的硬件交互效果，是候选演示素材。

待核实：准确板卡型号、准备环境步骤、原提示词与完整会话、人工配置/排错、失败重试、主动操作时间、最终效果。

尚不能证明：无嵌入式经验者可独立完成安装到运行全流程；玩家会持续使用或付费；厂商有购买意愿。

后续验证候选：请一位真正没有嵌入式经验的人自行选择一个小创意，在现有板卡上尝试；记录全部人工帮助与环境准备，不只记录提示词。当前先保留，不与 C01 同时开展产品开发。

## 本周判断依据

先弄清 C01 是否结论正确、验证充分、对同事有实际用处。随后看对方是否主动提供第二个问题、接受明确交付范围，以及谁可能为解决它付钱。

若现行通用 agent 已经能同样顺畅完成，则调查 Yoma 的集成、信息获取或交付便利是否仍有价值；没有额外收益就收缩该方向。案例失败或证据不足同样记录，不能只保留成功结果。
