# 工程档案与项目记忆

打开工程，直接在对话里让 agent「检查这个工程，保存确认过的工程配置」或「记住这个调试结论，并注明适用板卡和依据」。

## 首次接入

1. 自动识别会读取工程描述文件，不运行命令。支持 STM32 `.ioc`、Keil `.uvprojx`、IAR `.ewp`、CMake、Makefile、PlatformIO 和 ESP-IDF 的常见标记。扫描限工程根目录及两层子目录、400 个目录项；多个芯片候选不会擅自选一个。
2. 检查并补全芯片、板卡版本、构建命令、固件相对路径、探针、日志连接和验证方法，然后保存档案。识别结果是建议，不是已验证结论；复杂工程可让 agent 继续分析。
3. 让 agent 使用现有命令工具运行原始构建，检查实际退出码与日志。成功只表示构建命令通过，不表示已烧录或硬件验收通过；把确认过的结果及依据保存为记忆。

工程识别和记忆加载不会自动运行构建。工具链本机路径继续在「工具链」管理。


## 记忆如何工作

- **工程知识**：板卡约定、模块职责、用户确认的限制。
- **调试经验**：已查明的原因、有效排查方法、容易复发的问题。
- **任务交接**：完成了什么、仍不确定什么、下一步怎样验证。

每条都有标题、内容、适用范围、依据、来源会话和更新时间。「已验证」必须有依据，但依据真实性仍由 agent 和用户核实；未经实测的推断使用「待验证」。可以在对话里要求 agent 检索、更新或忘记具体条目。

Agent 的系统提示要求它在重要任务结束前通过 `project` 工具保存有效经验和交接。用户也可直接说「记住这个结论」。这是模型调用工具的工作流程，并非后台自动摘录所有聊天；突然关闭、取消或模型未执行保存时，未写入的内容不会成为长期记忆。

每次模型生成前读取档案及最近 6 条启用记忆的摘要，其他记录由 agent 按关键词检索（支持中文与英文）。已经打开的会话也会读取更新。停用或删除后不再主动注入，工具检索也不返回停用记录；**已有聊天、已发送给模型的内容不会被追溯抹除**。删除会保存标题的不可逆摘要，阻止 agent 按同一标题自动重建；它不能辨认所有换标题的同义内容，也不是对通用文件工具的安全沙箱。

多会话写入使用文件锁与版本检查，版本过期会报冲突，不会覆盖其他会话的更新。Agent 需要重新读取最新版本，再合并修改。最多 200 条记忆，状态文件上限 512 KB；有意限制规模，避免完整聊天记录挤满上下文。

## 文件与隐私

```text
<工程>/.yoma/project.json           工程档案，可提交 Git
<工程>/.yoma/knowledge/.gitignore   忽略本机运行数据
<工程>/.yoma/knowledge/state.json   记忆、删除标记、最近构建记录
```

工程范围取最近的档案、记忆目录或 Git 根（支持 Git worktree），不自动在不同工程、不同 worktree 或不同机器间合并记忆。构建输出和记忆默认不进入 Git，不另传记忆服务；被读取的内容会发送给用户所选模型，因此不要保存密钥或不希望发送给模型的内容。固件路径必须在工程内，状态目录不允许用符号链接指向其他位置。

这是工程接入和长期记忆功能。会话历史压缩、代码检查点、文件回滚、任务隔离和硬件验收仍各有职责，工程记忆不能替代它们。
