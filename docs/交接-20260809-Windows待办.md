## 这一跑暴露的 bug(已修)

### 判据证据在 Windows 上变成乱码

三条判据全过,但回填的证据长这样:

```
xTickCount@0x200002a8: 24920 -> 25665 (?=745) | ????????
g_bench_magic@0x20000010(D): 0xB00C0DE5,???? 0xB00C0DE5 | ????????
```

stdout 不是终端时 Python 用 `locale.getpreferredencoding()` 编码,中文 Windows 上那是
**cp936(GBK)**;而调试台按 UTF-8 解管道。解出来的替换字符**不可逆** —— 把它编回字节
再按 GBK 读只会得到"锟斤拷"。证据在写进信箱之前就已经毁了。

退出码不受影响,所以**裁决是对的**。坏掉的恰恰是这套系统的产品:证据。而且它不会报错,
只会安静地把每一轮的观察变成问号 —— 下一轮 agent 读到的就是这堆问号。

修法:`grader.ts` 的环境契约里钉死 `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1`。

**关于它的测试**:第一版写成"跑个打中文的 Python,断言证据不花"—— 那在开发机上
**不注入也照样过**(macOS locale 本来就是 UTF-8),是一个永远不会响的闸门。实测确认后
改成断言机制本身:判据进程一定收到 `PYTHONIOENCODING`。移除修复后它确实会红。

## 昨晚之前修的(与这一跑相关)

1. **克隆目录带上分支** + `ensureClone` 核对分支 —— 换分支时复用旧克隆会让 init 死在
   `src refspec run-1 does not match any` 上。
2. **分支不一致时拦在动板子之前**(`pullReset` 最前面)。不拦的话工位端会照着**另一条
   分支上的任务**烧片跑判据,跑完才在 push 时失败。
3. **判据解释器在 PATH 命中后真跑一次自检** —— Windows 的"应用执行别名"是个 exit 9009
   的桩,以前被归成"判据没过",会让研发端接着烧轮次去修一个不存在的 bug。
4. 冒烟脚本停守护走 SIGTERM(以前 SIGKILL 漏孤儿)、stdout 换 TextDecoder。
