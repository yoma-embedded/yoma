## 1. 目标与度量

产出三类数字,每轮评测都要有:

1. **通用 coding 能力**:Terminal-Bench 2.1(89 题)pass@1 与 pass^3;aider-polyglot(225 题)通过率;SWE-bench Verified 子集。
2. **harness 贡献**:**同一个模型**下 `yoma` vs `Terminus 2`(官方中立 agent)vs `OpenCode`(yoma 前端的祖先)的差值。
   榜上没有任何 DeepSeek 行,绝对分无参照,**这个差值才是 yoma 的成绩**。
3. **嵌入式**:closed-loop ESP32/QEMU 5 题通过率(零硬件);IoT-SkillsBench(真板,人工验证)的 CF/BF/BC 三态计数。

每轮附带:总花费(USD)、总 token(input/output/reasoning/cache)、每题步数、工具 isError 率(按工具/action)、
provider 错误数(`TurnResult.errors`)。**这些是"改进"那半的输入,不是装饰。**

**成功标准(第一圈)**:拿到一张"同模型三 harness"的 TB 2.1 表,人工读完全部 yoma 失败 transcript,
写出第一份 `docs/EVAL-agent-<日期>.md`,里面有 ≥3 条可执行的改进项。分数本身不设目标。

## 2. 总体架构

```
harbor run -d terminal-bench/terminal-bench-2-1 --agent yoma_agent:Yoma  # 要 PYTHONPATH=packages/bench/harbor -m deepseek/deepseek-v4-flash-vision-exp -n 3
   │
   ├─ 每题一个 Docker 容器(任务自带 environment/Dockerfile)
   │     install():  装 node(抄 opencode.py:nvm,musl 回退)+ 上传 yoma-eval-entry.mjs
   │     run():      node /installed-agent/yoma/yoma-eval-entry.mjs --cwd "$PWD" --instruction-file … --out /logs/agent/yoma-result.json --events /logs/agent/yoma-events.jsonl
   │                  env: DEEPSEEK_API_KEY, YOMA_PROVIDER, YOMA_MODEL, YOMA_THINKING, YOMA_EVAL_TIMEOUT_MS
   │     post_run(): 读 result.json → context.cost_usd / n_input_tokens / n_output_tokens / n_cache_tokens;(P2 后段)events.jsonl → ATIF trajectory
   │
   └─ verifier: tests/test.sh → /logs/verifier/reward.txt(0/1)  ← 判据不归我们管
```

`yoma-eval-entry.mjs` 内部 = `runTurn`(bench 已有)→ `createKernelHost`(压缩 / 重试 / 思考档位 / 13 个工具 / 会话 JSONL 全部白得)。
**不用 `example/99-headless-run.ts`**:它是裸 harness,没有压缩与重试,思考档位缺省 `off`。

模型目录:入口经 `resolveModels` 注入口自建注册表(faux 假模型走的就是这个口),在 pi-ai 内建目录之上追加
`deepseek-v4-flash-vision-exp`。产品代码零改动。

设计要点:
- **`resolveModels` 注入意味着 `runTurn` 跳过 `session.setModel`**(turn.ts 明写:注入的注册表里可能只有假模型),所以注册表返回的 `model` 就是被测模型,思考档位走 `defaultThinkingLevel`(= `job.model.thinking ?? DEFAULT_THINKING_LEVEL`)。
- 容器内隔离:`--config-dir /logs/agent/yoma-config`(技能/上下文/凭据;SkillsBench 把技能目录挂到这里的 `skills/`)、`--sessions-root <config-dir>/sessions`(会话 JSONL 随 Harbor 的 logs 一起收走,可拿回桌面端回放)。
- 超时:`hardTimeoutMs` 默认 50 分钟(bench 默认 60 分钟太长),可被 `YOMA_EVAL_TIMEOUT_MS` 覆盖;Harbor 的 `task.toml` 另有 agent 超时,以小者为准。
- 引擎:容器里没有 `engines/`,7 个嵌入式工具照常注册、调用时返回修复指引 —— 这是 **as-is** 配置,先量它。`coding-only` 配置(只装 read/bash/edit/write)需要 kernel host 开口(`session-manager.ts` 装配处),**P3 跑完第一轮再决定要不要做**。

## 4. 关键设计细节

### 4.1 模型目录补丁(为什么必须有)

- pi-ai **0.84.2(仓里钉的)与 0.84.3(最新,08-24)** 的 `providers/data/deepseek.json` 都只有 `deepseek-v4-flash` 与 `deepseek-v4-pro`;vision-exp 08-21 才发布。
- `resolveModel()` 的不变式是"注册 == 内建目录",`YOMA_MODEL=deepseek-v4-flash-vision-exp` 直接抛 `Model … not found`。
- 即使有条目,`input` 必须是 `["text","image"]`:pi-ai 的 `openai-completions` 在 `model.input.includes("image")` 为假时**静默丢掉工具结果里的图片**(`datasheet view_figure`、`la` 预览就白发了)。
- 条目:`api:"openai-completions"`、`baseUrl` 同、`compat` 同(`maxTokensField:"max_tokens"`、`thinkingFormat:"deepseek"`、`requiresReasoningContentOnAssistantMessages:true`)、`contextWindow: 1_000_000`、`maxTokens: 384_000`、`cost` 抄 v4-flash(0.14 / 0.28 / cacheRead 0.0028)。
- **未知项**:推理模式。公告与 vision 指南都没提。P3.1 用一条真实请求定;不支持就 `thinkingLevelMap` 全 `null`,并在报告里写明"无推理"(CLAUDE.md 实测:关了推理的 agent 一步一句话,从不停下来想)。
- 底座是 V4-Flash-**0731**;对照组用目录里的 `deepseek-v4-flash`(latest 别名),报告注明。
- 补丁住在 `packages/bench/src/eval/models.ts`,**不动 `acp/models.ts`**。pi-ai 收录后由漂移测试提示删除。要进产品(桌面端也能选它)另议。

### 4.2 记账

- `TurnResult.usage.cost` 来自 pi-ai 定价表 × 我们的条目,**首跑必须人工核 ≠ 0 且量级对**。
- `TurnResult.errors` 收 provider 抽风(内核自动重试 3 次,失败当数据不进 `stopReason`),必须进表,否则"网络抽风"会被记成"模型不行"。
- 每题 `elapsedMs`、`toolCalls.length`、按工具的 `status === "error"` 计数,从 `result.json` 直接汇总。

### 4.3 隔离与可复现

- 模型 + 档位钉死在跑批脚本里,两个人跑出来的数才可比。
- 每题独立容器(Harbor 保证);容器内 `configDir` / `sessionsRoot` 都在 `/logs/agent/` 下,不读宿主的 `~/.yoma`。
- 数据集钉版本(`terminal-bench-2-1` 的具体 revision 写进脚本)。

### 4.4 Windows

- Harbor 自身在 Windows 原生能否跑以实测为准(它调 Docker CLI/SDK;可能有 POSIX 假设)。跑不通 → `wsl --install -d Ubuntu`,在 WSL2 里 `uv tool install harbor`,Docker Desktop 开 WSL 集成。
- ESP-IDF + QEMU 那条(P4)直接在 WSL2 或 Docker 里做,不折腾 Windows 原生。

## 5. 风险与坑

| 风险 | 应对 |
|---|---|
| TB 题目的容器没有 node(很多是 python/ubuntu 基础镜像) | 适配器照 `opencode.py` 装 nvm;musl(Alpine)走打包 node 回退 |
| `bash` 工具默认 120 s 超时 | 描述里已写"长构建请调大";先不改,看 transcript 里有没有因此失败的 |
| 嵌入式口径的 system prompt 与 7 个无引擎工具在通用题上是噪声 | 先量 as-is;差距大再做 coding-only 配置对照 |
| cost 静默为 0 | 首跑人工核;`eval/models.ts` 单测断言三项单价非 0 |
| vision-exp 是 `-exp`,可能改行为或下线 | 报告记模型 id + 日期;对照组永远带 `deepseek-v4-flash` |
| DeepSeek 限流 / 抽风 | `-n` 并发先 4;`errors` 进表;整题重跑而不是改数 |
| 数据集下载大(SWE-bench 镜像) | SWE-bench 先抽 50 题;TB 2.1 镜像按题拉 |
| faux 不能当评测夹具(cost 硬写 0,token 是估的) | faux 只给入口与适配器自己的测试用 |
| 探针是模块级全局 | 真板评测串行、一题一进程(P5) |
| 纯 node 下等内核事件会把进程放空 | `runTurn` 里的 keepalive 是承重的,入口不绕开 `runTurn` |
| 中文 Windows 子进程 GBK | 容器里是 Linux,不受影响;真板(P5)在 Windows 工位上要记得 `PYTHONIOENCODING` 那条已在 `getShellEnv` 钉死 |

### 与计划的偏离

| 计划里写的 | 实际 | 原因 |
|---|---|---|
| `eval/models.ts` 用 `createProvider` 重建 provider | 改成**展开覆盖 `getModels`** | `api`(ProviderStreams 实现)只在 `CreateProviderOptions` 里、不在 `Provider` 接口上,重建时 `input.api.stream` 读到 undefined 直接抛。pi-ai 的 `createProvider` 返回纯对象字面量、方法全是闭包不依赖 `this`,包一层是安全的 |
| 入口就是 `entry.ts` 一个文件 | 拆成 `run.ts`(逻辑)+ `entry.ts`(壳) | 顶层 `main()` 让测试没法 import;与 `turn.ts` ↔ `turn-entry.ts` 同一条分法 |
| — | 新增 `--faux` 通道 | 零 key 验证整条 Harbor 链路,CI 也能用。**不能当评测夹具**(cost 硬写 0) |

### 实施中踩到的四个坑(都写进了 `harbor/README.md`)

1. **PyPI 的 harbor 0.22.0 与 GitHub main 的 0.22.0 内容不同**(版本号没跟着动):
   main 有 `harbor.agents.capabilities.AgentCapabilities`,PyPI 版没有、用 `SUPPORTS_ATIF: bool = True`。
   适配器对着**实际安装的 PyPI 版**写;`evals/harbor` 那份 clone 只作源码参考,别照着它改。
2. **中文 Windows 的 GBK 控制台会让 Harbor 当场崩**:rich 进度条用盲文点字符 `U+2826` 画动画,
   GBK 编不了,`UnicodeEncodeError` 把整个 run 带走。必须 `PYTHONIOENCODING=utf-8 PYTHONUTF8=1`
   —— 与 yoma 自己在 `getShellEnv` 里钉的是同一类坑,这次轮到我们当受害者。
3. **`--agent` 要 Python 模块路径,不是文件路径**:`import_symbol` 走 `importlib.import_module()`。
   把目录挂 `PYTHONPATH`,写 `--agent yoma_agent:Yoma`。
4. **job 名不能复用**:同名目录 config 不同时抛 `FileExistsError`,不会自动换名。
