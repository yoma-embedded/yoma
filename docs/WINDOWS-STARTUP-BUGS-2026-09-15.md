# Windows 启动问题验收（2026-09-15）

## 三项处理

### 启动时闪现 OpenCode 图标

原因是桌面 renderer 等语言字典期间仍渲染旧 `Splash`。改为复用现有 Yoma `Logo` 字标。
隔离的真实 Electron 窗口捕获了启动 DOM，确认显示 Yoma、没有旧 Splash，随后完成页面点击验收。

### 第一次启动模型目录旧，第二次才更新

`ensureModels()` 原来只缓存完成结果，没有共享在飞的解析。首屏多个组件同时请求时各建一份注册表，
后台刷新第一份后，较晚完成的另一份会把它覆盖。磁盘缓存已经更新，本次界面却仍读旧表。
受控时序测试成功复现：五个请求建五份表，后台完成后没有 `model.updated` 事件。

修正为共享一个解析 Promise；凭据变化重置解析与自动刷新标记，晚到的旧解析不能覆盖新结果。
模型名称、档位、上下文或价格变化也推送更新。保持后台联网，离线仍可打开会话。
前端回归确认 `model.updated` 使当前页面更新，晚到的旧响应不能盖回旧目录。

新模型仍以远端目录实际返回为准，没有手写 DeepSeek 4.1 条目。
本机对 `https://pi.dev/api/models/providers/deepseek` 的单次直连探测曾报 `ECONNRESET`；
竞态回归使用受控目录响应，不把它当成公网始终可达的证明。网络恢复后可在设置中“刷新模型列表”，无需重开应用。

### 手册访问旧地址且提示自建服务器

内置的是公共服务**地址**，检索服务在远端。本机不需要启动一份手册服务器。
用户报错中的 `http://47.122.120.208` 已退役，当前源码默认 `http://47.122.110.137:8301`。
Windows 实测：旧地址连接失败；新地址 manifest 返回 200、757 条记录，包含 STM32F3。
检查时当前进程/用户/机器环境变量和 `~/.yoma/.env` 未找到该旧覆盖，无法确定报错进程当时的具体配置来源。

修正：环境或配置文件中残留的旧官方基址在解析时改用当前默认，不改用户文件。
自建地址、显式参数和 `off` 保持原意，不对任意失败地址自动切换服务器。
移除 `ensureDatasheetServerEnv`，避免把首次文件解析结果永久固定为优先级更高的环境变量。
失败文案说明内置远端服务、实际配置来源和排查方法，仍禁止凭记忆编造芯片事实。

实际将旧地址注入新版工具后，`chips STM32F3` 成功返回 4 本手册、12 个分卷。
这只证明家族索引可查，不代表 STM32F303 的每份目标手册都已收录。
