# 施工指南:例程库(examples)

2026-08-13。例程驱动开发的第一期:离线索引 + 检索/种子工具 + 方法论技能。
账本(合并前资源预检)与 LLM 卡片富化是下一期,本文档只圈定已动工的部分。

## 这是什么、为什么

嵌入式开发的正确起点不是空白 main.c,而是**一份已被厂商验证过的例程**:一份能跑的
例程是几百个耦合决策(时钟树、引脚复用、DMA 通道、链接脚本、编译宏)的压缩证明。
agent 从例程出发做加法,失败模式是"改坏了什么"(可回退);从零生成,失败模式是
"几百个决策里猜错了哪个"(不可归因)。

学术侧的依据(Duke IoT-SkillsBench,arXiv:2603.19583):真硬件上行为失败远多于编译
失败(Zephyr 15:3);**LLM 自己合成的平台上下文让成绩变差**(24→19),人类专家写的
拉到 39。例程 = 可执行形态的专家上下文。产品侧的空位:Embedder(YC S25)四条路线
(EMBEDDER.md / 就地模仿 / SDK 划禁区 / 真机闭环兜底)全部**假设你已有工程**,
从零起工程明确不管 —— 例程驱动填的正是这个 0→1。

三个问题挂在三个已有机制上,不发明新概念:

- **知道**:examples 工具的 promptSnippet 进系统提示词;方法论技能进 `<available_skills>`。
- **理解**:索引给地图(每例程一张卡片),agent 用 read/bash 读中选例程本体。
- **选对**:代码只做硬过滤(芯片/生态是物理可用性,是事实核查不是裁决),
  软偏好与最终拍板归模型 —— 与"代码不裁决任何东西"同构。

## 数据形状

### 索引文件:`<configDir>/examples/index/<语料slug>.jsonl`

第一行 header,之后每行一个条目。容错读(坏行跳过、schema 标签对不上当没有)、
原子写 —— 照抄 `core/toolchain/ledger.ts` 的纪律,这份文件是缓存,不许成为失败点。

```
header: { schema:"yoma/examples-index@1", corpus, ecosystem, root?, commit?, generatedAt, entries }
entry:  { id, corpus, ecosystem, path, name, title?, summary?, targets[], board?,
          peripherals[], deps?, configKeys?, acceptance?, buildable, buildNote?,
          license?, loc, files, extractorVersion }
```

- `id` = `<语料id>/<相对路径>`,全局唯一;`path` 一律正斜杠。
- `targets` 全小写(esp32c3 / stm32f4)。**查询芯片按前缀匹配条目**(查 stm32f407
  命中 stm32f4;查 esp32s3 不命中 esp32)——家族级语料(Cube)标家族,芯片级
  元数据(esp-idf 的 Supported Targets 表)标具体芯片。`targets` 为空 = 元数据缺失,
  **不排除**但在结果里明说,让模型自己核对。
- `buildable` 是"底盘资格":语料根上必要件齐不齐(Cube 看 Drivers/ 是否实体,
  esp-idf 恒 true 但 deps 非空时 buildNote 记"需联网取组件")。**可读与可作底盘是
  两个承诺**:供体只需可读,底盘必须 buildable。
- `acceptance`:例程自带的验收素材(esp-idf 的 pytest_*.py)。厂商 CI 的判据就在
  语料里,绿点验证不必从零想。
- `extractorVersion`:抽取规则演进后能识别旧索引该重建。

### 本机语料账本:`<configDir>/examples/sources.json`

```
{ schema:"yoma/examples-sources@1", corpora:[{ id, ecosystem, root }] }
```

语料在哪台机器的哪个路径是**本机事实**,与 toolchains.json 同一档纪律:不进 git、
容错读、原子写、configDir 必须可注入(测试一律 mkdtemp,Bun 的 homedir 启动即定死)。
CLI `index` 成功后写入;工具靠它枚举可用索引、seed 时定位语料根。

**服务器演进的接缝就在这一层**:今天 corpora 条目是 `{id, ecosystem, root}`(本机
目录);以后服务器形态是 `{id, ecosystem, url}` + 本机缓存目录 —— 索引照常整份下载
(几 MB),例程本体在 seed 时按需取回缓存。search 只读索引、不碰语料文件,天然不用改;
要改的只有"语料根解析"一处。**现在不写这段代码**,只把语料文件访问集中在 indexer、
seed 与 enrich 三处,别处一律只读索引。

### 富化文件:`<configDir>/examples/enrich/<语料slug>.jsonl`(2026-08-14 起)

模型离线读完每个例程后写下的卡片,回答脚本抽不出来的两问:**它到底干了什么**
(summaryZh + capabilities)与**拿它合并要付什么**(footprint:引脚/外设实例/
链接期会重定义的符号/任务优先级/分区)。合并预检吃的就是 footprint。

```
每行: { schema:"yoma/examples-enrich@1", id, corpus, commit?, model, enrichedAt,
        card:{ summaryZh, capabilities[], footprint:{ pins[{pin,role?,note?}],
               instances[], symbols[], entrySymbols[], tasks[{name,priority?}],
               partitions? }, notes? } }
```

与索引不同的三条纪律(理由都写在 `enrich-schema.ts` 文件头):

- **旁挂,不进索引本体**:索引是脚本秒级重建的缓存,富化是花过钱的模型产物,
  重建索引不许冲掉它。读侧按 `(id, commit)` 合流,语料换版本旧卡片按陈旧跳过,
  同 id 后写覆盖先写(重富化 = 再追加一行)。
- **逐行自描述、没有文件头**:追加不需要先读,断点续跑天然成立(缺哪条补哪条),
  坏一行的爆炸半径就是那一行。
- **净化再落盘**:summaryZh 缺失整卡拒收;instances/symbols/entrySymbols 只收
  `\w+` 标识符 —— 实测 deepseek-v4-flash 会把提示词示例照抄成
  `Error_Handler(若存在)`、往 instances 里塞中文散文,散文进了冲突键,预检就会拿
  两段中文互相"撞车"。**机械过滤比措辞管用**(措辞也加了,双保险)。

## 抽取器(按生态分派,各带版本号)

抽取器是插件:元数据约定随 SDK 版本漂移是实测事实(这版 Zephyr 把 sample.yaml 改名
tests.yaml),文件名与格式不许写死在公共路径里。**语料应钉 release 分支**——esp-idf
master 已删 legacy I2C 驱动,跟 master 会把"API 世代"信息做没。

### esp-idf(`espidf.ts`)

- 例程判定:目录含 `main/` + 根 `CMakeLists.txt`,排除 `common_components`;
  从 `<root>/examples/` 递归。
- `targets`:README.md 的 `| Supported Targets | ESP32 | ... |` 表(实测在首行),
  归一化小写去连字符。无表 → targets=[](未知,不排除)。
- `title`/`summary`:首个 `# ` 标题 / 标题后第一段(截 400 字符)。
- `peripherals`:路径段(peripherals/i2c → i2c)+ `main/` 源码 include 映射
  (driver/xxx.h → xxx,esp_wifi.h → wifi,mqtt_client.h → mqtt,nvs_flash.h → nvs,
  esp_http_client.h → http,BLE 头 → ble 等)。
- `deps`:`main/idf_component.yml` 的 dependencies 键(逐行正则,跳过 idf 自身;
  不引 YAML 库 —— 与 toolchain 的 jsonc-lite 同一取舍)。
- `configKeys`:sdkconfig.defaults 的 CONFIG_XXX 键名。
- `acceptance`:pytest_*.py。
- `loc`:main/ 下 .c/.h/.cpp 行数。

### STM32Cube(`stm32cube.ts`)

- 遍历 `Projects/<板>/{Examples,Examples_LL,Examples_MIX,Applications}/<外设组>/<例程>/`。
  Demonstrations 不进 v1:板专属大杂烩,检索噪音远大于种子价值。
- **官方 Cube 语料没有 .ioc**(F1/F4/H7 三包实测 0 个)——配置在代码里,元数据在
  readme.txt(doxygen 风格):`@page <tag> <标题>`、`@par Example Description` 后的
  段落(截到下一个 @par/@note)。.ioc 解析留给"用户工程侧账本"(下一期)。
- `board` = 路径板名;`peripherals` = 外设组小写 + Src/ 源码的
  `stm32xxxx_hal_yyy.h` / `_ll_yyy.h` include。
- `targets` = 语料级注入(CubeF4 → stm32f4):固件包整包一个家族。
- `buildable`:语料根 `Drivers/` 下 HAL 驱动与 CMSIS 是否实体非空(F1 是子模块结构,
  没拉子模块时 false + buildNote 讲清怎么补)。
- `license`:包级 BSD-3-Clause。

## 搜索(`search.ts`,纯函数)

```
searchIndex(entries, { ecosystem?, target?, board?, peripherals?, keywords?,
                       buildableOnly?, limit=12 }) → ScoredExample[]
```

- **硬过滤**(排除,不降权):ecosystem 不符;target 前缀不匹配(targets 为空除外);
  给了 peripherals 却一个都不沾;buildableOnly 时非 buildable。
- **打分**(确定性,结果带 reasons):外设命中 ×3;keyword 命中 title/name +2、
  summary/path +1;board 命中 +3;buildable +2;小种子偏好(loc <200 +3,<500 +2,
  <1000 +1)—— 你要在它上面做加法,越小越好审。
- 排序:score 降序 → loc 升序 → id 字典序,同输入必同输出。

为什么不是向量库:工程级语料两千余份,硬约束(芯片/SDK)本来就该结构化过滤 ——
纯 embedding 会把 STM32 的 I2C 例程排到 ESP32 需求的第一位,语义完美、物理不可用。
候选进了 12 条以内,重排器就是读结果的 agent 本身。语料扩大再议向量层。

富化接入(第三个可选参数,富化表):有卡片的条目,外设匹配并上模型标的能力词
(脚本抽不到的 lowpower/ota 靠它),关键词弱命中多一份中文摘要可搜,命中行直接
带模型摘要。没有富化时行为与从前逐字相同 —— **富化只增益,不改底线**。

## 富化管线(`enrich.ts` + CLI `enrich`)

索引条目 → 挑证据密度最高的文件进提示词(main/*_it/*msp* 优先,conf/system_
脚手架不进,单文件 8k 字、总预算 32k 字)→ 模型写卡 → 净化 → 追加落盘。

- **模型调用是注入的**(`EnrichCompletion`),`enrich.ts` 不 import pi-ai:测试注入
  假模型,CLI 经 acp 的 `resolveModel` 装真模型 —— 管线正确性与哪家模型无关。
- 缺省模型 `deepseek/deepseek-v4-flash`(与 bench 的 DEFAULT_MODEL 同一取舍),
  `--model provider/model` 可换;费用按 pi-ai 的 usage.cost 累计后打印。
- **失败不落盘**:重跑本命令自动补齐缺口(把失败也记下来,就得发明"重试失败"的
  第二套机制)。单条内置一次 2s 退避重试,扛限流与瞬时 5xx。

## 合并预检(`preflight.ts`,纯函数)

底盘 + 供体的足迹放一起,凡能确定性算出的**重叠事实**一条不漏:引脚(归一后同键,
角色相同附"共享总线可接受"提示)、外设实例、符号(链接期重定义)、任务优先级
(跨条目同值)、分区表(两方都自带)。跨生态直接一条"物理不可能"早退。

三条设计底线:

- **报重叠,不裁决** —— 两个例程同挂 I2C1 同一对引脚可能正是共享总线的正确姿势。
  与"代码不裁决任何东西"(bench 不变式)同构:代码只保证事实完备,判断归模型。
- **盲区必须大声说**:没富化的条目预检看不见,报告点名列出,绝不拿沉默冒充干净。
- 引脚归一(`normalizePin`)只做确定性等价改写(GPIO_NUM_4/io4 → GPIO4),
  不做猜测(PB1 与 PB01 是否同脚随家族而异,不动)。

## 工具(`tools/examples.ts`)

四个 action,归编码组(createCodingToolDefinitions,与 toolchain 同档:它回答
"这个工程从哪来",不依赖 engines):

- `search`:上述查询参数 → 紧凑列表(id/标题/targets/外设/loc/buildable/得分与理由,
  有富化时附模型摘要)。没有任何索引时报人话:sources.json 在哪、CLI 怎么跑,给出确切命令。
- `info`:单条整卡 + 例程目录顶层文件清单 + 富化足迹(有卡片时)。
- `preflight`(ids,底盘在前):合并前把重叠事实报出来,见"合并预检"节。
  details 记参与条目与重叠条数。
- `seed`:把例程拷进工作区(默认 `<cwd>/<例程名>`,目标已存在且非空则拒绝)。
  排除 build/、sdkconfig(保留 sdkconfig.defaults)、managed_components/。
  写 `<目标>/.yoma-seed.json`(schema:"yoma/seed@1",id/corpus/commit/sourcePath/
  seededAt)—— 出处要可提交、可追溯。输出按生态给下一步:esp-idf 给
  `idf.py set-target/build/flash monitor`;Cube 例程引用固件包相对路径
  (../../../../Drivers),v1 不改写路径,如实告知 sdkRoot 并建议两条路
  (包内构建,或按工程结构调整 include)。**如实报告限制,不假装种子自包含。**
- promptGuidelines 压缩六步纪律(这是产品端每个会话都生效的通道):
  新功能先 search 从已验证例程起步;seed 后先原样跑通再改;一次一个能力、步步验证、
  失败回上一个能跑的提交;芯片/SDK 是硬约束,targets 不含你芯片的不用。
- 语料文件访问(seed 的拷贝)直用 node:fs 并注释理由:语料根来自本机账本,不属于
  会话执行环境;远程语料时这里换下载缓存层。工作区侧(目标路径、provenance)走 env。

## CLI(`core/examples/cli.ts`)

```
bun packages/coding-agent/src/core/examples/cli.ts index     --ecosystem esp-idf --root <路径> [--corpus <id>] [--config-dir <dir>]
bun packages/coding-agent/src/core/examples/cli.ts enrich    [--corpus <id>]... [--model <provider/model>] [--concurrency <n>] [--limit <n>]
bun packages/coding-agent/src/core/examples/cli.ts search    --target stm32f4 --peripheral i2c --keyword dma [--config-dir <dir>]
bun packages/coding-agent/src/core/examples/cli.ts show      <id>
bun packages/coding-agent/src/core/examples/cli.ts preflight <底盘id> <供体id>...
bun packages/coding-agent/src/core/examples/cli.ts list
```

`index` 缺省语料 id = `<ecosystem>@<git 短 commit>`(git rev-parse 失败给日期)。
`enrich` 缺省跑全部语料、只补缺口(`--limit` 试跑控费)。索引器与 CLI 是离线运维
工具;以后搬服务器,跑的就是这同一组命令。cli.ts 不在桶文件里,kernel 的编译单元
盖不到它 —— 改动后用 kernel 同款 tsconfig 手动核一遍类型(本次实测过一次)。

### 富化实测(2026-08-14,deepseek-v4-flash,并发 6)

全量 2654 条约 30 分钟、~$3.5(2700 余次调用);中断后重跑只补缺口(实测四语料
"已有 N,本次成 0"收敛)。质量抽查:Cube 卡片的符号栏就是经典合并冲突集

跑批修出来的三条(前两条各埋了回归测试):
