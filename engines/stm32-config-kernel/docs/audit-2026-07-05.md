# 功能审计报告 — 与 CubeMX 主要功能的差异(2026-07-05)

方法:6 个独立探测器通过真实 CLI 走「配置→validate→generate→arm-gcc 编译→与 CubeMX 规范输出比对」,只读不改仓库。结论按证据分级:
**WORKS_VERIFIED**(全链路实证等价)/ **GENERATES_BUT_SUSPECT**(生成但有实质缺陷)/ **VALIDATES_ONLY**(校验通过但代码生成为空)/ **CANNOT_EXPRESS**(配置文档无法表达)。

## 一、外设覆盖实测矩阵

| 外设/功能 | 判定 | 证据要点 |
|---|---|---|
| USART 异步(F1+F4) | ✅ WORKS_VERIFIED | 黄金测试;init/MSP/NVIC/it.c 全链路,编译经 arm-gcc |
| GPIO 输出/输入/EXTI | ✅ WORKS_VERIFIED | EXTI 含共享向量去重、handler 生成;编译验证 |
| I2C(F1,含 remap) | ✅ WORKS_VERIFIED | PB6/7 与 PB8/9 remap 联动正确,跨组 hint 正确拒绝;编译通过。缺陷:句柄名 `hi2c21`(应为 `hi2c1`,实例名数字提取 bug)、缺 `OwnAddress1 = 0` 行、GPIO 速度 LOW vs CubeMX HIGH |
| 时钟树(求解+校验+代码) | ✅ WORKS_VERIFIED | 72M/100M 求解、Flash 延迟/VOS 自动、APB 上限、ADC 分频约束自动(DIV6 + PeriphClkInit 正确发射)、USB refEnable 门控 |
| SPI 主机(F1+F4) | ⚠️ GENERATES_BUT_SUSPECT | Init 结构体逐字段正确;**但 HAL 模块未接线**(hal_conf 缺 `HAL_SPI_MODULE_ENABLED`、缺 include、`_hal_spi.c` 未复制未入 CMake)→ 生成工程不编译(补 3 行即通过)。硬件 NSS 寄存器配置静默错误(条件求值 bug,见 §二-2) |
| TIM PWM | ⚠️ GENERATES_BUT_SUSPECT | Base_Init/PWM_Init 正确且编译通过;**但 `HAL_TIM_PWM_ConfigChannel` 未发射**——`Pulse` 被静默丢弃,PWM 实际不出波。通道级 ConfigForMode(`*_ConfigChannel_CHx`)未实现 |
| ADC | ❌ VALIDATES_ONLY | `MX_ADC1_Init` 是空壳,无 MSP、无模拟 GPIO 初始化。根因:CubeMX 的 `ChannelRegularConversion` 是信号量激活的 RefMode(选中通道即激活),不是模式树叶子——引擎未建模该机制,Rank/SamplingTime 无处安放(报 PARAM_INACTIVE)。时钟侧约束反而全对 |
| DMA | ❌ CANNOT_EXPRESS | 配置文档无 dma 字段;`DMA` 当外设配置可走到请求→通道模式树(证明 IR/引擎底座在),但需要用户显式设置 USART Mode 参数才能过条件(§二-2 的同一 bug),且代码生成零输出 |

## 二、审计暴露的跨切面 bug(按严重度)

1. **HAL 模块接线以 hal_mode 驱动,漏掉无 HalMode 的 RefMode(SPI 等)**——hal_conf 使能宏 / include / HAL 源码复制 / CMake 源列表四处联动缺失 → 生成工程不编译。这是"生成即可编译"承诺的直接破洞。影响:SPI 确认,凡 RefMode 无 HalMode 属性的外设类推。
2. **参数默认值未上黑板/未发布 PossibleValue 信号量**(engine/session.rs 参数解析只对用户显式设置的参数发布信号量)→ 条件引用其它参数默认值时判 false:SPI 的 FirstBit/CLKPolarity 合法列表值被 PARAM_RANGE 误拒、硬件 NSS 解析到错误重载(寄存器静默错配)、DMA 请求条件 `S_USART2_TX_RX` 不满足。**这是引擎语义层最深的一个偏差。**
3. **实例数字提取 bug**:`I2C1` → digits "21"(应为 "1")。影响句柄命名(`hi2c21`)与 `$Index` 宏展开。位置:engine/modes.rs `bind_ident` 与 codegen 句柄命名(同一逻辑)。
4. **GPIO 电气预设未取高速变体**:SPI SCK/TIM 输出应按 db 的 AF-PP-HighSpeed 预设发 `GPIO_SPEED_FREQ_HIGH`,现发 LOW(F1 2MHz 压摆率,4.5MHz SCK 有信号完整性风险)。
5. **TIM 通道级配置**:`ConfigForMode` 的 `IC/OC_ConfigChannel_CHx` 通道索引块 + `TIM_CHANNEL_x` 实参传递未实现。
6. **空值字段跳过 vs CubeMX 显式发 0**:`OwnAddress1 = 0;` 类字段缺行(靠全局零初始化侥幸等价,复用到栈上/重初始化即错)。

## 三、与 CubeMX 主要功能块对照(全景)

| CubeMX 功能块 | 本内核现状 |
|---|---|
| 器件选型(MCU Selector) | ✅ list-mcus/describe-mcu(无板卡/BSP,无功耗排序) |
| Pinout 引脚分配+冲突 | ✅ 等价甚至可解释性更强(回溯+诊断链);SWD 保留;F1 remap 组;跨引脚互斥 |
| 外设 Mode&Configuration | ◐ 引擎层通用(任意 IP 的模式树/参数/信号量都能校验);代码生成层见 §一矩阵 |
| Clock Configuration | ✅ 等价+超出(CubeMX 需手工点,本内核可从目标频率确定性求解) |
| NVIC 配置 | ◐ 每外设使能+优先级联动校验+it.c 生成;无全局优先级分组配置入口(固定默认) |
| DMA 配置 | ❌ v2(IR/数据底座已就位) |
| 中间件(FreeRTOS/USB/LwIP/FatFS) | ❌ 非目标(v1 明确排除) |
| 代码生成(main/msp/it/clock/gpio) | ✅ 结构等价:MX_ 命名/USER CODE/MSP 顺序;再生成保留用户代码(CubeMX 同款能力) |
| 工程输出 | ◐ CMake+arm-gcc(CubeMX 还有 MDK/IAR/CubeIDE);HAL only(无 LL) |
| .ioc 工程文件 | ◐ 等价物是 JSON 配置文档(可入 git);不能导入 .ioc |
| 固件包管理 | ◐ F1/F4 子集打包;无版本管理器 |
| 功耗计算器 / 板卡原理图 | ❌ 非目标 |

## 四、结论

**核心命题已被证明**:通用语义引擎路线成立——时钟/引脚/校验/诊断/工程骨架与 CubeMX 等价且确定性更强,加新外设不需要新引擎代码。**当前真实差距集中在代码生成的三个机制缺口**(HAL 模块接线、通道式 ConfigForMode、信号量激活式 RefMode)加一个引擎语义缺口(默认值上黑板)。修完这四项,SPI/TIM/ADC 即达 USART 同级;DMA 需在其上加配置文档字段+通道分配+句柄连线,工作量约等于 NVIC 那一层。
